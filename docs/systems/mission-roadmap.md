## 下一阶段顺序

### 1. 补全 Active Mission 的单人可证明事实

优先处理：

1. `20017` 已按 CN 1.8.1 的主位首次弹射统计实现；
2. `20015/20016` 已从官方 CDN 建立技能动作效果索引，并匹配属性耐性下降、直接回复、比例回复和再生效果；
3. 下一批优先处理称号条件族，并继续覆盖字段缺失、异常数值、错误队伍、失败战斗和事务回滚。

缺少动作效果索引或无法确认统计语义时保持 fail closed，不按角色名称或中文文案推测。20015/20016 的
未解析角色、队伍快照边界和任务开放前是否预累计见[待审阅实现记录](mission-implementation-assumptions.md)。

### 2. 扩展简单称号

从剩余 16 条中按 pattern 分组，只选择当前存档或正式请求能够直接证明的条件。角色等级曲线、历史累计、缺少服务端权威来源的 MVP，以及尚未闭合所有权验证的魂珠设置不实现。

已完成第一批 `pattern=48` 第二玛纳板条件族：3 条全局节点累计和 472 条指定角色全板完成。其余称号继续按同一安全下界原则逐批处理。

### 3. 分批补全活动任务与 Pass

category 3 按 QuestRange、评级、房主/成员、阶段和 client check 拆分，禁止重新启用旧宽松 map。Pass 优先处理有明确单人事实的 pattern；救援来源不明确时不冒充普通 Guest，购买流程也不与免费轨混合。

战阵 type 80/81/82 的 12 条任务仅以 SET 编辑器成功保存 RAID 第 1 组主队伍、副 1、副 2 槽位作为权威事实。服务端请求无法证明用户是否点击过客户端“复制”按钮，因此不得把这批实现描述为复制按钮追踪。

## 明确延后

- 接取救援请求和 Attention：缺少权威救援来源，保持低优先级、fail closed；
- 回归任务：资格生产者完成前不向普通玩家开放；
- Active Mission `21030`：依赖尚未实现的 `multi_special_exchange` 活动入口；
- 完整数据库导入导出：本路线图不扩展所有任务事实的迁移格式；
- 角色等级近似计算：等待 CDN 提供权威 EXP 曲线。

## 每批完成门槛

每个条件族必须独立提交，并通过：

```bash
node tools/test-workflow/run.cjs --group integration:mission
node tools/docs_check.cjs
npm run build
bash scripts/check-hygiene.sh
git diff --check
```

提交后不自动 push。客户端验收由贡献者异步进行，不作为继续开发的前置条件；规则实现、架构文档和验收结果必须分别保持中文且不互相冒充。
