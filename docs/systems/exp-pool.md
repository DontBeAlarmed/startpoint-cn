# 经验池边界

## 结论

经验池的合法存档值是非负安全整数。经验池正好花完时，服务端写入并返回 `0`；“游戏内显示 `0`、存档却为负数”不是归零的正常结果，而是历史坏档、非法导入，或某个奖励/邮件写入了负数。

## 写入规则

- `/api/index.php/expod/inject_exp` 只接受正的安全整数经验消耗，拒绝负数、零、小数、非有限数和超安全整数。
- `updatePlayerSync` 与 `insertPlayerSync` 对 `expPool` 做统一非负安全整数保护。异常奖励不会静默写入负数；位于业务事务中的流程会随事务回滚。
- 数据库初始化会把历史 `exp_pool < 0` 修复为 `0`，并输出修复数量。这样客户端不会继续收到会被显示层截断的负值。

## 相关流程

```text
经验消耗请求
  -> 校验正整数
  -> 校验余额足够
  -> 事务内扣除经验池、增加角色经验、记录任务事实
  -> 返回同一事务后的 exp_pool
```

战斗、邮件、任务奖励和管理后台仍然通过玩家领域写入经验池；因此它们共享同一非负约束。若 CDN 奖励表本身包含负经验，服务端会拒绝对应经验池写入，不把 CDN 异常扩散为负值坏档。
