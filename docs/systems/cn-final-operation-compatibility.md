# 国服运营末期推测性兼容

本文集中登记官方 CN 1.4.54 主数据在运营末期存在空值或缺表、但客户端仍保留可见玩法入口时，服务端为维持可玩性提供的推测性兼容。这里的行为不属于官方 CDN 原始行为，也没有官方服务端响应作为证明；它们必须保持边界明确、可替换，不能扩展成通用的数据修复层。

Content Sync 仍只转换 CDN 中实际存在的字段，不复制其他活动数据。下列回退全部位于服务端业务层；未来 CDN 补丁给出完整定义或获得官方响应证据后，应优先使用精确数据并删除对应回退。

## 活动机兵瞩目奖励

活动入口机兵使用 `hard_multi_event`、`hard_multi_event_quest`、`periodic_reward` 和 `periodic_reward_point`。正常活动 `1/2/3/100000/100001/100002` 在活动表中明确提供 `periodic_reward_point_id`，关卡表提供 `battle_periodic_reward_group_id`，服务端按这些字段结算。

末期活动 `1001` 至 `1006` 仍属于 `hard_multi_event`，客户端掉落预览和关卡表仍保留周期奖励组，但活动级 `periodic_reward_point_id` 为空。服务端只对这六个精确活动 ID 启用推测性兼容：使用关卡的周期奖励组 ID 作为点数 ID。该映射只影响多人活动机兵成功结算；单人活动机兵不发瞩目奖励、不扣次数。

点数初始化、每日恢复和扣减读取 `periodic_reward_point`。每名真人玩家使用自己的存档次数；NPC 没有玩家存档，不领取奖励。失败、abort、重复 finish、次数为零均不发奖也不扣次数，奖励数量不乘服务端掉落倍率。

领主战入口机兵 `1061001` 至 `1066004` 来自 `boss_battle_quest`，没有 periodic reward 字段。它们明确排除在兼容之外，维持现有硬币掉落，不获得瞩目奖励或活动挑战任务。

## 狂热激战常驻批次

狂热激战 `700011` 至 `700017` 的活动自身代币、文件夹奖励和商店商品为空。业务层暂时使用 `eventId - 10` 映射到 `700001` 至 `700007` 的完整奖励与商品，并保留常驻活动自己的开放期。

该映射是推测性兼容，不是 CDN 原始配置。读取始终优先使用当前活动自己的非空数据；未来补丁补齐精确商品或文件夹奖励后，对应部分应停止回退。商店购买仍按全局商品 ID、库存、余额和时间段在同一事务校验。

## 替换边界

- 不根据活动名称、图标或文案推断关联关系。
- 不修改 CDN 转换器输出以伪造缺失字段。
- 不把活动机兵兼容扩展到 `boss_battle_quest`。
- 不把狂热激战的 `eventId - 10` 映射扩展到其他活动族。
- 新 CDN 给出非空精确数据时，业务层优先精确数据；无法自动替换的兼容项应先补权威测试再删除。

服务端自动测试只能证明上述受限行为稳定，不能把推测性兼容升级为官方事实。客户端实机结果记录在[测试进度](../status/test-progress.md)。
