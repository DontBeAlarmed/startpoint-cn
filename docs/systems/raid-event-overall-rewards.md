# 战阵事件级奖励

## 已实现范围

战阵（Raid）不是普通关卡的 `score_reward`。事件级累计奖励来自 CDN 主数据
`raid_event_overall_reward.json`，服务端在成功完成战阵关卡后，按当前事件的累计击破数选择奖励，并在同一个单人结算 SQLite 事务中完成：

1. 读取玩家当前事件的 `total_kill_count` 与 `received_up_to`；
2. 按关卡 `kill_count_weight` 增加累计击破数；
3. 选择本次跨过的总击破阈值、周期阈值和每击破奖励；
4. 发放道具、Mana 或星导石，并把结果合并到结算响应；
5. 保存累计击破数和已处理阈值，避免重复领取；
6. `/summary` 和结算响应返回当前 `raid_boss` 及 `kill_count_reward_data`。

状态保存在 `players_raid_events`，主键为 `(player_id, event_id)`。没有历史状态的存档从 0 开始，服务重启后从数据库恢复。

## 数据映射

| CDN 字段语义 | 服务端语义 |
|---|---|
| 总击破阈值 | 本次累计值从阈值以下跨到阈值以上时发放一次 |
| 周期击破奖励（带起始值） | 每跨过一个周期阈值发放一次 |
| 每击破奖励（无起始值） | 当前按本次 `kill_count_weight` 倍发放 |
| 奖励 kind 0 | 道具，响应 `kind=1` |
| 奖励 kind 2 | 星导石/宝石类，响应 `kind=3` |
| 奖励 kind 3 | Mana，响应 `kind=8` |

当前官方 CN 1.4.54 表中只出现上述三种奖励 kind。未知 kind 不会被猜测转换。

## 未确认边界

- “无起始值的每击破奖励”是否应按 `kill_count_weight`，还是按战斗次数或客户端定义的击破单位发放，服务端目前依据表字段和现有战斗数据采用前者，尚未通过客户端奖励动画与实收数量确认。
- `received_up_to` 当前记录本次累计击破值，并作为阈值幂等游标。官方客户端字段的更细粒度语义尚未通过抓包确认。
- 事件累计击破是否存在全服共享值不在本实现范围内；当前按项目的单存档体验目标持久化到玩家事件状态。

## 客户端验收清单

1. 首次完成战阵关卡，确认结算弹窗出现每击破奖励。
2. 一次跨过多个总击破阈值，确认所有奖励一次性出现且库存到账。
3. 重新进入战阵页面，确认累计击破数和 `received_up_to` 保持。
4. 重复完成不跨新阈值时，确认历史阈值不重复发放。
5. 关闭并重启服务后再次进入页面，确认状态不回到 0。
