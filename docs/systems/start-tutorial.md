# 首次教程状态与中断恢复

## 问题背景

首次注册教程会连续调用 `tutorial/update_step`。旧实现先写入下一步骤，再执行抽卡、角色发放、货币变更和邮件写入，因此进程异常、数据库异常或请求处理中断可能留下“步骤已前进，但该步骤副作用未完成”的半状态。

旧实现还把 `user_triggered_tutorial` 中的 ID `12` 当作首次教程完成标记。国服主数据中 ID `12` 实际是 `guide_to_quest` 引导提示，其触发条件包含首次礼物领取，并不是首次教程自身的完成状态。若该提示没有及时完成，服务端会在后续 load 中继续返回 `user_tutorial`。

客户端在 `InitializeRealRemote` 收到 `user_tutorial` 后会恢复为 `RestoreState.Tutorial`。`GlobalLogic.isGameSystemUnlocked()` 在教程恢复态下一律返回 `false`，因此自动战斗、合击位等原本由剧情进度解锁的系统也会继续保持锁定。这不是 CDN 数据偏差，而是服务端错误恢复了首次教程。

主要客户端依据：

- `pinball/remote/tutorial/updateStep/TutorialUpdateStepRealRemote.as`
- `pinball/loading/tutorial/TutorialEndLoadingTask.as`
- `pinball/common/data/tutorial/StartTutorialRepository.as`
- `pinball/context/global/GlobalLogic.as`
- `pinball/context/reproduce/LogicStatus.as`

## 服务端状态契约

`players.tutorial_step` 表示客户端当前可恢复的步骤：

| 流程 | 持久步骤 | 用于业务分支的有效步骤 |
| --- | ---: | ---: |
| 完整教程 | `step` | `step` |
| 简化教程 | `step` | `step + 11` |

有效步骤 `15` 是教程抽卡结果，`16` 是首次赠送，`17` 是教程终态。完整教程完成步骤 `16` 后结束；简化教程完成持久步骤 `5` 后结束。新实现完成终态请求时将 `tutorial_step` 写为 `NULL`，后续 load 不再返回 `user_tutorial`。

触发教程 ID `12` 只保留客户端引导提示的原始语义：

- ID `12` 已记录但首次教程仍未结束时，仍返回 `user_tutorial`；
- 首次教程已经结束但 ID `12` 尚未记录时，也不再恢复首次教程；
- 自动战斗、合击位等功能继续按各自剧情和触发教程条件判断。

## 事务与重复请求

单次 `tutorial/update_step` 在 SQLite 事务中完成：

1. 在事务内重新读取玩家步骤；
2. 校验请求完成步骤与持久步骤相符；
3. 执行抽卡、赠送、领取记录和邮件等副作用；
4. 最后推进持久步骤；
5. 任一写入失败时回滚本步骤的全部写入。

数据库 schema `9` 增加 `players_tutorial_step_receipts`，只保存每个玩家最后一次成功步骤的请求分支和完整 `data` 响应。回执与业务副作用、步骤推进在同一事务中写入。客户端可能在服务端已经提交、但响应没有到达时重发同一步骤；服务端把“持久步骤等于请求的下一步骤”识别为重放：

- 新事务产生的抽卡、赠送、改名、普通步骤和最终步骤直接重放原始响应；
- 抽卡重复角色产生的补偿道具、角色时间字段和改名结果不会在重放时丢失；
- 没有回执的旧步骤只使用持久状态构造兼容响应，不再次执行副作用；
- 跳过未来步骤或回退到更早步骤仍返回错误。

`skip` 只允许在持久步骤 `0` 且分支尚未选择时确定。进入完整教程或简化教程后，请求中的 `skip` 必须与 `tutorial_skip_flag` 一致，不能在中途切换分支。

## 旧存档恢复

load 前会处理旧版本可能留下的抽卡半状态：

- 有效步骤为 `15` 且抽卡角色 ID 为空时，原数据无法证明任一既有候选角色就是该次教程抽卡结果，因此一律退回前一步重新抽卡；
- 完整教程持久步骤达到 `17`，或简化教程持久步骤达到 `6` 时，直接视为已完成，不再返回 `user_tutorial`。

旧实现可能在赠送步骤 `16` 的多次独立写入之间中断。该状态没有专属领取流水，无法从历史数据严格区分“货币已加但领取记录未写”和“完全未发放”。服务端不对这类旧存档做推测性补发，避免重复增加货币；新事务实现会阻止后续继续产生该半状态。若确认旧存档缺少赠送奖励，需要按具体存档人工核对。

## 验证

专项测试 `tools/tutorial_update_step.test.cjs` 覆盖：

- 抽卡写入中途失败时步骤、货币和角色全部回滚；
- 抽卡和赠送步骤重复请求不重复扣费或发奖；
- 重复角色补偿、名称和客户端必填角色字段可原样重放；
- 教程分支不能在中途切换；
- 完整教程与简化教程均在最终步骤持久结束；
- ID `12` 与首次教程完成状态解耦；
- 旧终态和抽卡半状态在 load 时正确恢复。
