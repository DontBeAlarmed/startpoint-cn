# 多人救援碎片兼容奖励

## 目标与边界

银币碎片、金币碎片和紫币碎片是多人救援结算资源。当前服务端尚未完整恢复官服救援通知、救援来源和参与身份链路，而单人部署主要依赖 NPC 或普通多人房间，因此管理后台提供“所有成功多人结算均视作可发放救援碎片”的兼容开关。

该开关默认开启，属于服务端玩法兼容设置，不改变客户端协议。关闭后只停用本兼容奖励；现有多人入场、普通掉落、任务事实和其他结算奖励不受影响。

## 发放规则

一次多人 finish 同时满足以下条件时发放：

- 后台开关开启；
- 本次关卡成功完成；
- 当前多人关卡存在银、金或紫币碎片映射。

每次固定发放对应碎片 `×10`。所有成功房间使用同一规则，不区分房主、普通成员、NPC 或真实救援玩家；失败、中止、单人结算和未登记的关卡不发放。发奖位于现有多人 finish 总事务内，并受 active quest 幂等边界保护，结算回滚时碎片写入一并回滚。

支持范围包含永久领主、活动协力领主、世界故事活动领主、战阵协力和活动机兵等具有多人救援语义的关卡。碎片档位优先依据当前 CN 内容表中的关卡分组、难度和救援点数配置生成，不对未知分类或纯数字后缀作泛化猜测。

## 客户端显示

服务端使用统一奖励写入层增加玩家物品库存，同时把本次碎片放入 `item_list` 和 `drop_additional_reward_ids`，使客户端结算页与实际入包数量保持一致。

`490000`、`490001`、`490002` 是分别对应银、金、紫币碎片的本地兼容展示组 ID，不属于当前 CDN `additional_reward_rules.json` 的官方组。真实物品 ID `49000`、`49001`、`49002` 和库存数量仍是持久化权威。

## 证据等级

客户端与 CN 内容表能够支持碎片物品、多人关卡范围和难度档位；“每次固定 10 个”参考了已有玩家验证的部署实现。将所有成功多人房间统一视作救援来源，是为当前单人服使用方式增加的明确服主策略，不是官服行为复原。

后续恢复真实救援来源后，应新增独立的来源判定和客户端联机验收，再由服主关闭本开关；不应在本模块内混入房间发现、救援通知或跨服身份职责。
