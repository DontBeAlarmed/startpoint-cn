# 当前已知问题与限制

本文只保留尚未解决、明确受限或需要重新确认的问题。已经修复并通过客户端验收的历史问题由 Git 记录，不继续堆叠在这里。自动测试状态和客户端验收状态必须分别查看[支持矩阵](./support-matrix.md)与[测试进度](./test-progress.md)。

## 任务系统后续事项

任务模块当前仍只能标记为“部分完成”。本轮以称号审计收尾；下列 category 3、每日/每周客户端全流程和角色觉醒条件全集均已转入后续版本，不再作为本轮实现范围：

1. category 3 已覆盖 `2485/2512` 条事实：805 条原生严格协力规则、948 条已审计空 selector 兼容规则、257 条 type 23 精确通关规则、445 条关卡、物品、竞速、阶段、当前状态及单人累计规则、18 条 Event 入口/SET/投票事实、2 条歼灭者 type 86 及 10 条 type 87；剩余 27 条均为缺少权威来源的救援任务。空 selector 兼容和 Type 87 的水、雷、风、闪机兵仍待客户端验收；暗机兵条件统计已完成首轮实机取证。
2. Degree 已覆盖 1281 条有权威事实的任务。其余 7 条已按精确 ID 固定为延期集合：`3000`、`25000/25010/25020`、`70004/70005/70006`。其中 MVP 已按 CN 客户端 `statistics.is_mvp` 记录，魂珠使用已按成功 `/party/edit` 配置变化记录；两者仍不声称提供服务端独立反作弊重算。新增战斗统计只从升级后的成功 finish 开始累计。
3. category 1、2、10 的普通、每日、每周自动结算已有服务端测试，但奖励提示、跨日/跨周重置和重启持久化尚未通过 CN 客户端验收。
4. 角色觉醒 144 条均进入显式计算路径；`2310012` 种族合集与 `1610022/2610072` 全场无棺柩规则已有自动测试，但尚未由 CN 客户端实机验收，144 条任务条件仍不能标记为全部已验收。

角色觉醒的“立即解锁第二页、手动回第一页领奖”核心时序已经通过客户端验收，但这不代表 144 条觉醒任务条件全部正确。详见[任务完成度审计](../systems/mission-completion-audit.md)与[角色觉醒任务](../systems/character-awake-missions.md)。

战阵 type 80/81/82 的主数据文案包含“复制替换”，但 `/party/edit` 请求只足以证明玩家从 SET 编辑器成功保存了 RAID 第 1 组的目标槽位。当前实现不能证明用户点击过复制按钮；客户端按钮级操作语义仍属于不可观测边界。

## Pass 剩余边界

PassDaily、PassWeek、PassEvent 主数据、核心进度、点数、6 条 type 23 活动任务、19 条 type 85 主动发送表情周常和等级奖励已经接入。周常 type 20 救援和购买流程仍未实现，且尚未通过 CN 客户端全流程验收。详见[修行之道](../systems/pass-card.md)。

## 邮件通知待客户端验收

`/load`、邮件、任务、Active Mission、单人/多人结算以及装备、抽卡、商店和养成等主要成功写响应现在都按当前存档未领取邮件数动态计算 `mail_arrived`。读取、stub 和非成功 `result_code` 响应仍可能不携带该字段；客户端是否会在各主要写响应后立即刷新邮件提示也需逐类验收。

邮件附件领取已覆盖 12 种受支持类型；单领、全领、重复 ID、重复角色和异常回滚已有事务测试。枚举中的 13、14、16、17 缺少当前支持语义，继续 fail closed；客户端对 12 种附件和通知刷新的完整体验仍需专项验收。详见[邮件系统](../systems/mail.md)。

## 特殊关卡与联机

### 狂热激战常驻批次为推测性回退

官方 CN 1.4.54 主数据中，常驻批次 `700011` 至 `700017` 没有活动代币、文件夹代币奖励和商店商品。当前服务端把它们回退到 `700001` 至 `700007` 的配置，以提供可用商店和奖励流程；该映射有自动测试，但没有官方服务端抓包依据，必须保持“推测实现”标记，并等待客户端全流程验收。

活动列表中的末期机兵 `1001` 至 `1006` 也存在活动级周期点数 ID 缺失，但关卡奖励组和客户端瞩目奖励预览仍保留的情况。当前只对这六个活动启用精确回退；领主战机兵不在此范围。两类推测行为的完整边界见[国服运营末期推测性兼容](../systems/cn-final-operation-compatibility.md)。

### 战阵事件级奖励待客户端验收

战阵的本地三队配队、开始、基础结算和官方 `raid_event_overall_reward` 表驱动的累计击破奖励已经接入。finish 按 `required_kill_count` 推进共享 Boss 权重和分关卡次数，summary 在独立事务中发奖并推进玩家游标；10 个奖励槽、重复 summary 和事务回滚已有专项测试。客户端奖励动画、页面刷新和官方全服状态在单实例私服中的体验仍待验收；旧错误状态迁移及 summary 发奖时点见[战阵事件级奖励](../systems/raid-event-overall-rewards.md)。

### 超级猫头鹰多场景联机待客户端验收

服务端已在同一 active quest 内实现 `LevelNext`、第二代 SceneReady、第二次 BattleStart 和最终 Finalize，并按 CDN 字段限制 BothBoss 入口。当前缺口是 CN 客户端的 NPC/真人完整切场、第二 Boss、最终结算和异常断线体验验证；进程重启后的原房间与场景恢复仍不支持。详见[多场景联机分析](../protocol/super-owl-multiscene.md)。

### 自动连战体力耗尽

自动连战模式可能在体力耗尽后继续请求 start。服务端现已在 `is_auto_start_mode=true` 且体力事务明确失败时使用客户端端点内可处理的 `result_code=4050`，不扣资源、不创建 active quest；手动挑战仍按普通入场错误处理。该错误码的官方含义是关卡超出开放期，并非正常自动连战完成状态，客户端提示和返回目标仍需真机确认。正常次数耗尽应由客户端自身计数器收尾。详见[体力系统](../systems/stamina.md)。

### 奖励活动倍率待客户端验收

官方 `reward_campaign` 的道具、角色战斗经验、固定经验池和固定关卡 Mana 倍率已经接入单人、联机结算，普通与 Rare Score Reward、Weekly 周期、Boost 加法、取整、服务器掉落倍率和事务回滚均有自动测试。`additional_reward` 的官方单候选 Item、活动期、前置关卡、QuestRange、敌人等级累计阈值和单人/联机响应也已接入；多候选和非 Item 继续 fail closed，1.4.54 的 Boss Pickup schedule 没有可发奖励组。当前仍需在活动时间内用 CN 客户端确认掉落数量、结算显示和动画。详见[奖励活动倍率](../systems/reward-campaign.md)。

## 账号、存档与入口功能

### 存档完整性

导入、导出和克隆已覆盖多个领域，但尚无针对所有玩家域、可选字段、事务回滚和跨版本恢复的完整端到端矩阵。新增领域表后若没有同步序列化与恢复逻辑，可能出现部分状态缺失。大规模导入前应保留数据库备份并用测试存档验证。

### 礼包码兑换

真实礼包码校验、兑换内容、次数限制和持久化尚未实现。`load` 与能力检查均主动关闭客户端入口；兼容响应不等于礼包系统可用。固定响应的分类见[兼容空响应与未实现路由审计](../reference/stub-route-audit.md)。

## 内容与客户端资源限制

### 首次标题资源与动画资源

- 首次没有完整 CDN 缓存时，标题画面可能找不到 `scene/title_bundled/logo/logo.movie.amf3.deflate`；完整下载后通常消失，仍需在全新安装流程复核。
- 官方 CN 1.4.54 资源集中缺少 `character_level_up_effect.frame.amf3.deflate`，当前通过资源完整性边界避免恢复循环，但对应动画资源并未补齐。

### 卡池与漫画图片

- CN 1.4.54 缺少部分早期或联动卡池的 `gacha_feature_content`，手动切换到相应运营时间时可能出现 C2032。服务端无法凭空生成官方图片。
- 漫画图片处理曾针对特定高分辨率设备调整；其他屏幕比例、纹理上限和完整翻页体验仍需设备矩阵复核。

### Mana Board 时间窗

第二块玛纳板已按官方 `mana_board2_open_condition` 和统一服务器时间过滤；跨时间存档只在 load 响应中临时降级当前板索引，不清理板二节点或改写数据库。实现边界见[第二玛纳板开放期](../systems/mana-board-availability.md)。

## 待复核现象

以下现象缺少稳定复现或最新证据，暂不据此修改业务逻辑：

- 抽到新角色后，客户端可能把角色自动填入默认编队空位；需确认这是客户端原生行为还是服务端响应字段问题。
- 个别环境偶发 R1 连接失败，曾有“重建存档后恢复”的记录，但没有证明问题位于存档、网络还是旧客户端缓存。
- 角色剧情阅读后紫色未读标记是否能稳定清除，需要重新核对 `episode_trial` 的真实持久化协议。

复核结果应进入对应系统文档或测试矩阵，不在本文追加排查时间线。
