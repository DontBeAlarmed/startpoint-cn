## 分类口径

| 分类 | 含义 |
|---|---|
| **服务端可落地且已实现** | 条款有明确服务端语义，且有对应实现（file:line） |
| **服务端可落地未实现** | 条款有明确服务端语义但缺实现 |
| **纯客户端演算（不可对照）** | 战斗 DSL / 物理 / 状态机在客户端内存中演算，服务端仅透传结果；引用客户端类佐证 |
| **数据驱动（主数据已含）** | 条款内容是主数据表的投影，服务端承担内容分发，无逐条逻辑 |

判定纪律：战斗机制绝大多数条款为客户端演算——本线如实归类，只把真正有服务端面的条款（统计回声、结算、续战、自动续战、场地玛纳）单列。**战斗演算与抽卡不同，无 seed 复核机制**：服务端对战斗结果只做形状级校验（`single-finish-validation.ts` 字段白名单）与统计消费，属设计边界而非缺口（见结论）。

## 十、结论

1. **分类统计**：战斗余篇 7 个文件合计 **148 条**条款行（逐条/同构合并后）——**纯客户端演算 128 条**、**数据驱动（主数据已含）16 条**、**服务端可落地且已实现 4 条**（场地玛纳结算〔Yakumono L91，shop-misc 批已计〕、挑战失败单人结算面、续战、自动续战停止语义）、**服务端可落地未实现 0 条**。另有 5 个服务端面以「统计回声」形式并入纯客户端条款行的说明列（统计→任务计数、统计→称号/觉醒计数、终身计数、统计白名单校验、max_combo 存档），汇总见第八节。
2. **战斗机制条款的服务端面极薄**：伤害、特殊效果、敌人状态机、机关物理、领域效果全部在客户端 1.8.1 战斗 DSL 内演算（本线已逐条引用客户端类佐证）。服务端承担：内容分发（主数据 1.4.54）、结果形状校验（`single-finish-validation.ts` 37 字段白名单）、统计消费（任务/称号/觉醒/终身计数）、结算与续战生命周期。**帮助对这些服务端面条款的描述与实现一致，未发现偏差。**
3. **新发现（前批未审、本线确认的服务端可落地条款）**：
   - 自动续战停止语义：`is_auto_start_mode` + 体力不足 → result_code 4050（`auto-start-stop.ts`，单人/rush/raid 三路同构）——Battle_Battle.md L329-355 此前从未对照过；
   - `use_power_flip_lv3_count`/`coffin_count_reduced_count`/`encoffinment_count` 等区域统计字段与帮助条款（强化弹射 Lv3、棺柩计数减少、棺柩化）一一对应，作为称号/觉醒/收集任务事实被消费；
