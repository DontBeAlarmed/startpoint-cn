# Seris Power Flip Sound Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Correct all six Dragon King Power Flip timeline sound dependencies and verify a real battle starts on the device.

**Architecture:** `build_seris_effect_containers.py` remains the authoring source of truth for the six AMF3 timelines. A decoded-timeline regression test binds all human PF levels to the packaged new water-rise sound and all dragon PF levels to the packaged new dragon-breath sound, after which the existing whole-character build and release pipeline carries the regenerated timeline bytes into a new release.

**Tech Stack:** Python 3, `unittest`, `wf_dsl` AMF3 codec, `wf_character_flow.py`, Fastify CN server, MuMu device shell.

## Global Constraints

- Human Lv1-Lv3 must use `sound_effect/unique/se_seris_water_rise`; dragon Lv1-Lv3 must use `sound_effect/unique/se_seris_dragon_breath`.
- Do not edit EntityList CSVs because both new sound payloads are already present and declared in the Dragon King package.
- Do not change PF visuals, action DSLs, tables, gameplay values, player saves, app data, or APK installation.
- Preserve unrelated dirty-worktree files; do not reset, clean, overwrite, or commit user WIP.
