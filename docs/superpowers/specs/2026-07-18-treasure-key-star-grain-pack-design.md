# 宝物域钥匙与星之粒素材箱修复设计

> 日期：2026-07-18  
> 范围：宝物域入场钥匙、星之粒属性培育素材箱  
> 不包含：狂热激战商店商品逻辑

## 背景

本轮修复两个互相独立的问题：

1. 宝物域 `2001～2006` 挑战后，示宝金钥匙 `500000` 未减少。
2. 星之粒兑换所的六种属性培育素材箱购买后，只发放第一项奖励，其余素材缺失。

狂热激战常驻活动的商店涉及客户端商品主数据、复刻活动映射、有效期和库存语义，作为后续独立功能从头梳理，本设计不调整相关代码或数据。

## 宝物域钥匙

### 根因

CN 主数据中，宝物域 `2001～2006` 的 `battle_startable_use_item_mode` 为 `Always`，每次开战需要 `500000 ×1`，同时消耗 10 点体力。`scripts/gen_entry_costs.js` 只生成体力，并把所有道具成本写死为 `itemId: 0, itemCount: 0`，导致 `/single_battle_quest/start` 不进入道具扣除分支。

### 设计

- 在入场成本生成器中为 ChallengeDungeon 读取字段 `56/57/58/70`，分别得到道具模式、道具 ID、数量和体力。
- 生成期断言宝物域六关均为 `500000 ×1`、体力 10，避免以后重建资产时再次丢失道具成本。
- `/start` 在同一个 SQLite 事务内完成成本校验、钥匙扣除、体力扣除和 active quest 持久化；任一步失败时全部回滚。
- 使用已有 `insertActiveQuest` 持久化入口，不再只写内存 `activeQuests`。
- `/start` 成功响应返回扣除后的 `item_list`，余额为 0 时也必须返回，以便客户端立即删除库存项。
- 每次 `/start` 只扣 1 把钥匙。自动周回的后续轮次会分别发起新的 `/start`，不能把 `auto_start_times` 乘进入场成本。

### 错误处理

- 钥匙不足或体力不足时返回失败，钥匙、体力和 active quest 均保持不变。
- 本轮不扩展通用结算幂等协议，不新增结算响应缓存；该问题作为关卡事务架构的后续工作记录。

### 验证

- 资产测试覆盖 `13_2001～13_2006` 的道具和体力成本。
- 路由/业务测试覆盖 4 把钥匙连续挑战后余额依次为 `3/2/1/0`。
- 第五次开战失败且没有部分扣除。
- 响应 `item_list[500000]` 与数据库余额一致，包括 0。
- TypeScript 编译和现有特殊关卡测试保持通过。

## 星之粒属性培育素材箱

### 根因

商品 `100017～100022` 不是可放入背包后使用的箱子，而是购买时立即展开的六项奖励组合。CN 主数据的六个奖励槽位从索引 `25` 开始，每组三个字段。`tools/rebuild_star_grain_shop.ts` 只解析第一组 `25～27`，运行资产因此只保留 `10001 ×1`。

### 设计

- 生成器依次解析奖励槽起点 `25、28、31、34、37、40`。
- 空槽跳过；非空槽必须具有合法类型、ID 和正数量，否则生成失败。
- 重新生成 `assets/star_grain_shop.json`，六个属性素材箱各包含完整六项奖励。
- 保持 `/shop/buy`、`givePlayerRewardsSync` 和 `/load` 不变；这些路径已经支持多项 ITEM 奖励。
- 不创建 ID 为 `100017～100022` 的背包道具，也不接入 `/item/use_item`。

### 验证

- 资产一致性测试逐项比较 CN 原始六槽与生成后的 `rewards`。
- 六种属性素材箱均应包含 6 项奖励。
- 火属性商品 `100017` 必须为 `10001×1、1×175、2×140、3×75、4×25、99×25`，其余属性按主数据对应元素 ID 验证。
- 购买数量大于 1 时所有奖励按倍数发放，同时遵守库存限制。
- 购买响应和重新 load 后的 `item_list` 与数据库一致。
