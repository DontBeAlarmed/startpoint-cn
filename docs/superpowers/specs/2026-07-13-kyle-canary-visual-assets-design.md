# 凯尔金丝雀角色全套视觉资产设计

## 目标

将现有金丝雀角色 `119999` 换成参考图中的白狼骑士“凯尔”，覆盖游戏内立绘、头像、缩略图、战斗 UI、cut-in、剧情图和战斗像素动画，同时不影响任何官方角色。

参考图：`E:/sora——picture/OC/角色设计/狼骑士/早期凯尔/ChatGPT Image 2026年7月11日 09_42_19.png`。

## 范围

- 保留角色 ID `119999` 及现有战斗数据、词条、队长技和技能效果。
- 将角色资产标识从共享的 `resistance_princess_3halfanv` 分离为独立的 `kyle_wolf_knight`。
- 覆盖所有必要视觉资产：基础/觉醒立绘、技能 cut-in、图标合集、头像、缩略图、战斗 UI、连锁 cut-in、剧情横幅和剧情表情。
- 覆盖常规及特殊像素图，并保留可播放的 atlas、frame、timeline 数据。
- 本轮不生成语音；把金丝雀当前语音复制到新的 `kyle_wolf_knight` 路径继续沿用。视觉金丝雀通过后再设计台词和 TTS 批处理。

## 方案

### 资产隔离

先为 `119999` 建立角色快照。复制视觉模板到新的 `character/kyle_wolf_knight/` 逻辑路径，并同步角色 `code_name`、立绘定位、裁剪表及所有新路径索引。`action_skill` 保持现有键，避免改变战斗技能。

### 立绘与 UI

以用户参考图作为身份、服装和配色基准，生成一张适合移动 RPG 的透明背景角色母版：白色狼头与长毛、冰蓝眼睛、银白长衣、灰蓝披肩与饰带、银色花纹、黑色长靴。不得增加其他角色、文字或水印。

基础立绘使用克制的英雄站姿；觉醒立绘保持同一身份和服装，增加冰蓝魔力与更强姿态。其他 UI 图从这两张母版确定性裁切和缩放，确保各界面角色身份一致。图标合集保持模板 atlas 的原尺寸和矩形布局。

### 像素动画

采用 `black_wolf_knight` 的像素骨架和时间轴作为模板，因为其种族、体型和骑士动作最接近凯尔：

- 常规 atlas：137 个条目。
- 特殊 atlas：57 个条目。
- 保留全部动作序列、碰撞圆、锚点和播放区间，并把 AMF3 内部的 `character/black_wolf_knight/` 引用重映射为 `character/kyle_wolf_knight/`。
- 在模板像素上重绘角色区域：黑狼改为白狼，红黑铠甲改为银白长衣与灰蓝装饰，保留黑靴和清晰轮廓。
- 技能火焰/红色特效改为冰蓝、银白特效；不改变每帧边界或 atlas 坐标。

像素图由确定性脚本完成调色、区域修正和重新封装，AI 只提供像素风格参考，不直接生成最终 atlas，以避免帧漂移和动画抖动。

## 生成与导入流程

1. 快照 `119999`，并 dry-run 资产分离。
2. 生成并审核基础、觉醒两张角色母版。
3. 去除背景并验证 alpha 边缘；白色毛发不得出现色键污染。
4. 生成各类 UI 图和图标合集，保持模板尺寸及布局。
5. 重绘两张像素 sprite sheet，保留 `black_wolf_knight` 的六个 AMF3 配套文件。
6. 运行模板完整度检查，确保必要资产 100%。
7. dry-run 导入，写入时自动备份并加入 pending。
8. 发布 common、medium、android 三类增量包，重启游戏验证。

## 安全与回滚

- 不覆盖 `resistance_princess_3halfanv` 或 `black_wolf_knight` 的任何原始资产。
- 所有生成物先落在 `work/ai_canary/kyle_wolf_knight/`，确认后才进入 store。
- 写入前保留角色快照和逐文件 `.bak-wfmod-*` 备份。
- 任一步失败时停止发布；客户端异常时用角色快照恢复 `119999`。

## 验收

- 模板检查必要资产达到 100%，且所有 PNG 可解码、尺寸符合目标资产要求。
- 立绘、头像、队伍缩略图、战斗 UI、技能 cut-in 中均显示同一个凯尔形象。
- 常规待机、前后移动、技能准备、胜利及两段特殊动作可连续播放，无越界、闪烁或旧角色残帧。
- 发布后客户端只增量下载，不触发全量重下。
- 邮件领取、角色一览、详情页、编队和一次实际战斗均不崩溃。
