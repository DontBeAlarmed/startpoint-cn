### 平衡性决策（保留的激进项，均为用户明确指示）

- **次数上限 ×5（封顶99）**：暖机/团队 buff 上限大幅拉高（1570 行）——玩家侧强度大增，由 boss 血量 ×2.5 与"基线组数值不动"对冲。
- **开局技能槽一律满**（640 处）：开局节奏彻底改变，属"好玩优先"的全局设定。
- **技能能量 ×0.85（v1 已生效）+ 充能 ×1.5 + 技能槽限≤3去限**：技能循环轴显著加速，注意个别角色可能接近无限连发（艾莉亚式，刻意为之）。
- **Fever 引擎（Fever点×2 + 延长×2）**：Fever 覆盖率上限明显提高，光系受益最大（补弱意图）。
- **演武/无限血量档 29 条还原原值**：分数挑战计分环境不受全局缩放污染。
- 辅助/治疗/坦克伤害倍率减半、稀有度梯队（三/四星 95% 基线、专精值分层）与基线组零通胀原则保持。

## 三、使用方法（一键/可选不发/分享）

```
双击 mod-tools\一键平衡包.bat
  → 自动展示 dry-run 统计
  → 输入 Y  = 应用 + 发布 CDN + 打分享包
  → 输入 A  = 仅应用（不发布，游戏内不生效，可再手动 wf_publish）
  → 其他键 = 退出，不做任何修改
```

命令行等价：
```
python mod-tools/wf_balance_suite.py                     # dry-run
python mod-tools/wf_balance_suite.py --apply             # 只写数据表（不发）
python mod-tools/wf_balance_suite.py --apply --publish   # 一键下发
python mod-tools/wf_balance_suite.py --export-pack       # 打「WF平衡增强包-<时间>.zip」
```

**分享给别人**：`--export-pack` 生成的 zip 内含 CDN 增量包 + 使用说明——对方只需把
`archive-common-diff/pinball-*.zip` 丢进自己 startpoint-cn 的 `.cdn/cn/archive-common-diff/`，
重启游戏即自动增量下载生效（服务端动态扫描，无需重启服务端）。

## 四、防护与回滚

- **marker 防叠加**：`logs/balance_suite_applied.json` 存在时拒绝重复 `--apply`（倍率类改动会叠乘）；
  与 v2 互斥（检测 v2 marker 会中止）。
- **自动备份**：全部写入带 `.bak-wfmod-suite-<时间>`（boss 走 `.bak-wfquest-*`）。
- **回滚**：还原各表备份 → `wf_publish.py --tables ability,leader_ability,character_status,boss_level,ability_soul,weapon_ability` 再发一版。
- 前置依赖：`wf_all_analysis.py` / `wf_unique_mech.py` 的 logs JSON（已生成；改设计后先重跑这两个）。

## 五、已知边界

- 新增/移植行的**界面描述文字**沿用目标键首行，效果生效但文案不更新。
- 「发动技能动作」类组件未纳入自动流水线（需逐角色金丝雀验证，见龙兽专案 G 组件）。
- 独特机制分发每项最多服务 4 人，保持稀有感；菜单不足的属性个别角色标"(菜单不足)"。
- 装备侧只动数值/次数，不加行；魂珠强度同步后低练度装备即满强度（练度系统弱化，刻意）。
