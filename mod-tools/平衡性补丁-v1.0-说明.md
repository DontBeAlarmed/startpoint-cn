# 全角色平衡性增强补丁 v1.0（2026-07-09）

> 资源版本 1.4.57 → **1.4.58**（`pinball-1.4.57-1.4.58-1-mod07090038.zip`）
> 执行脚本：`mod-tools/wf_balance_patch.py`（默认 dry-run，`--apply` 写入）
> 明细报告：`logs/balance_patch_v1_report.json`（每个角色/技能/boss 的逐条改动）

## 一、设计理念

以**各属性最后推出的五星角色**为强度基线（下称"基线组"），把老角色整体拉向基线，
而不是把强者继续加强——避免数值通胀失控。基线组本身数值零改动，只参与新机制。

**基线组的划分**（每属性）：正编编号（`1x1xxx`）末尾 5 个五星 ＋ 联动编号（`1x3xxx`）＋
特殊编号（999999 夏可缇）。如火＝威尔弗雷德/瓦格纳(顶点)/珂艾特/莉莉丝/佩妮萝涅＋黄金船＋夏可缇。

实测基线组 Lv100 均值（HP/ATK）：
火 3295/769 · 水 3839/911 · 雷 3848/936 · 风 3874/931 · 光 3894/766 · 暗 3784/883
——老五星比基线普遍低 10%~30%，四星/三星整体再低一档，这就是本补丁要填的差距。

**适用范围**：rarity≥3 的全部玩家角色 **473 个**（五星 235/四星 158/三星 80）。
剧情助战（`700xxx`）与敌方单位不受影响。

## 二、改动内容

### A. 解除主位限制（全角色）

- 词条 `unisonable`：`false → true`，共 **1029 行 / 522 个词条键**。
  原本标 Ⓜ（仅主位生效）的词条现在放协力位也生效。
- 前置条件 `202 (OwnerIsMain)` → `0`（仅清 c6/c13/c20 三个前置列，未动其他同值列），
  玩家角色词条中已全部清零。
- 表中仅剩 25 行 `false`，均为非玩家单位（助战/系统词条），刻意不动。

### B. 属性专精词条（新机制，全角色 +473 行）

每个角色在其**第一个专属词条键**（全部 473 角色都有专属键，不会污染共用词条）追加一条
常驻新词条，方向按属性划分，呼应各属性的主流打法：

| 属性 | 专精方向 | 效果枚举 | 常驻实现 |
|---|---|---|---|
| 火 | **技能伤害**UP | during 2 SkillDamage | HpLow≤100%（恒真） |
| 水 | **技能充能效率**UP（协力循环） | during 3 SkillGaugeCharging | 同上 |
| 雷 | **直击（协力球/弹珠撞击）伤害**UP | during 1 DirectDamage | 同上 |
| 风 | **弹射伤害**UP（含强化弹射） | during 23 PowerFlipDamage | 同上 |
| 光 | **Fever 期间攻击力**UP | during 0 AttackPoint | during_trigger 4（Fever 中生效） |
| 暗 | **能力伤害**UP | during 154 AbilityDamage | HpLow≤100%（恒真） |

- "恒真常驻"用官方已有先例（90020/90052 的 `HpLow 阈值100%`）实现，非自创结构。
- 新行 `unisonable=true`：协力位也吃属性专精。
- 目标=自身，数值不随技能等级变化（SLv1=满级）。

**强度分层**（光属性因带 Fever 条件，数值 ×2 补偿）：

| 层 | 划分 | 专精值 | 光属性 |
|---|---|---|---|
| 五星·初代（老三分之一） | 正编序号最早段 | +15% | +30% |
| 五星·中期 | 中段 | +12% | +24% |
| 五星·近代 | 新段（基线前） | +10% | +20% |
| 五星·基线组 | 末5+联动+特殊 | +8% | +16% |
| 四星（全部） | — | +12% | +24% |
| 三星（全部） | — | +15% | +30% |

设计意图：越老/越低稀有度补越多，但单条 8%~15% 的常驻增益在本作词条体系里属温和档
（官方常驻词条常见 20%~55%），不会让任何老角色反超基线组整体强度。

### C. 基础数值（HP/ATK）向基线靠拢（388 个角色）

每个非基线角色按 `系数 = clamp(属性基线均值×稀有度比 ÷ 当前Lv100值, 1.0, 涨幅上限)`
分别对 HP、ATK 等比缩放**全部等级断点**（1/10/80/100，成长曲线形状不变）：

| 层 | 目标（基线均值×） | 涨幅上限 |
|---|---|---|
| 五星·初代 | 100% | ×1.20 |
| 五星·中期 | 100% | ×1.12 |
| 五星·近代 | 100% | ×1.06 |
| 四星 | 85% | ×1.15 |
| 三星 | 75% | ×1.18 |

- **只加不减**：已经高于目标的字段系数取 1.0（如瓦格纳 HP 3511 本就高于基线均值→不动，
  ATK 739→769 补到基线）。
- 保持稀有度梯队：四星/三星目标分别取基线的 85%/75%，不会与五星混淆定位。
- 例：玛丽娜（火·初代五星）ATK 640 → 768（撞 ×1.20 上限），HP 3709 不变。

### D. 技能能量需求 ×0.85（459 个技能键）

全部玩家角色主动技的 `min_skill_weight`（SLv1）与 `max_skill_weight`（满级）
统一 ×0.85（四舍五入，≥1）。例：白虎 580→493；基础技/＋/＋＋各级别同步下调。
所有属性开技速度整体提升 ~18%，配合水属性专精（充能效率）形成明确的技能循环轴。

### E. 全部副本 Boss 血量 ×1.5（531 条）

`boss_level` 全表血量基础值 ×1.5（覆盖 hit/fix 两种血量模式，22 类副本的 boss 全部生效；
等级曲线不动，等比放大）。例：zegura（夏活）400→600。
用意：玩家侧全面增强后，把练度检验线同步上移，避免副本全面白给。
Boss 攻击力/TP 未动——提升的是耐久压力，不是秒杀风险。

## 三、平衡性自检

1. **基线组数值零通胀**：新五星 HP/ATK/词条数值完全不动，只拿最小档专精（8%）与能量减免——
   相对地位不变，仍是各属性天花板。
2. **老角色不反超**：数值封顶到基线均值，专精差距（15% vs 8%）仅 7 个百分点，
   不足以翻越新角色的机制优势（多段词条/队长技/形态切换）。
3. **稀有度梯队保留**：三/四星目标数值仅为基线 75%/85%，专精略高是"可用性补偿"，
   定位仍是过渡/特化选择。
4. **敌我同步上调**：玩家均值增强约 10%~20%，boss 血量 +50%，实际通关压力略增，
   鼓励利用新机制（协力位词条全解锁 + 属性专精配队）。
5. **结构安全**：新词条行全部采用官方已有的行结构先例；只清主位前置 202，
   未触碰 OwnerIsUnison(203) 等对偶限制；CSV 全表往返校验无损后才写入。

## 四、生效与验证

```
① python mod-tools/wf_balance_patch.py            # dry-run 预览
② python mod-tools/wf_balance_patch.py --apply    # 写入（自动 .bak-wfmod-balance-*/.bak-wfquest-* 备份）
③ python mod-tools/wf_publish.py --tables ability,character_status,action_skill,boss_level
④ 重启游戏（服务端动态扫描 diff，无需重启服务端）
```

写入后读回校验已通过：
- 瓦格纳词条键 1110011 第 3 行 = 技能伤害+15% 常驻行 ✓
- 玛丽娜 Lv100 ATK 640→768 ✓ · 白虎技能能量 580→493 ✓ · zegura 血量 400→600 ✓
- 全表剩余 unisonable=false 仅 25 行（均非玩家角色）✓ · 前置 202 清零 ✓

游戏内快速抽查建议：
1. 编队里把瓦格纳放**协力位**，看原 Ⓜ 词条是否生效（主位解除）。
2. 角色详情看词条区是否多一条（描述文本沿用该键首行，显示为原词条文案；实际效果以数值面板为准）。
3. 打一场老图，感受技能条变快；开 Fever 用光属性看伤害跳变。
4. 任意 boss 战血条明显变厚（+50%）。

## 五、回滚

- 一键回滚：恢复 4 张表的备份文件（`*.bak-wfmod-balance-20260709-003745` ×3 +
  `19/a4aa….bak-wfquest-20260709-003746`），再 `wf_publish.py --tables ability,character_status,action_skill,boss_level` 发一版即可。
- GUI「改动日志」页也可逐条回溯。
- 重复执行保护：`logs/balance_patch_v1_applied.json` marker 存在时 `--apply` 拒跑（防叠加），
  确需重跑用 `--force`。

## 六、已知边界

- 属性专精行的**词条描述文本**沿用目标键首行 string_id（与 GUI 添加行同法）：游戏内不会出现
  "技能伤害+15%"的新文案，效果真实生效但界面文字不变。想配文案需改 ② 层文本资产，另行处理。
- `AbilityDamage`（能力伤害 UP）官方仅 3 行使用，属于冷门枚举，暗属性专精如遇个别角色
  无能力伤害手段则该条为空转（角色本身无能力伤害时自然无收益），属预期内。
- 能量 ×0.85 对能量本就极低的技能（<10）因取整可能无变化。
